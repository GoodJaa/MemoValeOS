# Uncertainties

What this project does not yet know.

> Record an uncertainty instead of writing a confident sentence. See [[Knowledge-OS/Rules/Brain-Rules]]. One ledger per project, at `Project-OS/04-Research/Uncertainties.md`; the validator's `blocking-uncertainty-on-active` reads it from there.

## Ledger

| ID | Uncertainty | Status | Blocking | Resolution source | Next action |
|---|---|---|---|---|---|

## Rules

- Status is one of: open, resolved, accepted-risk, out-of-scope.
- Blocking means work cannot proceed correctly until the uncertainty is resolved.
- Knowledge affected by an open blocking uncertainty stays draft. See [[Knowledge-OS/Protocols/Knowledge-Maintenance-Protocol]].
- An uncertainty is resolved by evidence, not by deciding it no longer matters.
- A resolution is recorded under its own dated heading, `### U-NNN resolved (YYYY-MM-DD)`, naming the evidence.

# Backlog: идеи по ОС

Сток для идей по устройству самой ОС (Knowledge OS / Project OS / Tools), возникающих во время работы над проектом. Правка кода ОС вне этого файла — только если она блокирует текущую задачу проекта; иначе идея записывается сюда одной строкой и ждёт отдельного прохода.

Это A0 из апстримного аудита (`MemoValeOS-backlog-2026-08-27.md`, GoodJaa/MemoValeOS): без стока идеи утекают прямо в код, и рабочая копия расходится с апстримом без учёта.

**Статус записи — это раздел, в котором она лежит, а не фраза внутри абзаца.** До 2026-09-22 он писался прозой («Закрыто (hash, дата)»), и файл дорос до состояния, когда закрытое и открытое лежали вперемешку: раздел «Открытые» содержал четыре записи, закрытые неделю назад. Перекладывая запись из раздела в раздел, оставляйте в её теле хеш и дату — они говорят, чем закрыто; раздел говорит только, закрыто ли.

Разделы: **Открытые** — ждут работы. **Требуют решения** — ждут выбора владельца, а не кода. **Ожидают условия** — работа названа, но делать её рано, и условие названо явно. Закрытые записи и архив перенесённого из `OS-Backlog.md` лежат в `Backlog-Archive.md` рядом с этим файлом. Архив — летопись проекта, где ОС разрабатывается, и в апстрим с os-v5 не переносится; поэтому здесь он назван путём, а не ссылкой.

**Закрытая запись сразу уезжает в `Backlog-Archive.md`** — сверху его раздела «Закрытые», с хешем и датой в теле. Здесь остаётся только то, что ещё ждёт работы, решения или условия: этот файл читают, чтобы выбрать следующее дело, и сделанное в нём — чистая цена контекста. До 2026-10-02 закрытое копилось здесь же и занимало около 61 из 76 КБ.

- **2026-10-02 · Нет пути «задача во внешнем трекере → Task». Предложение: `/mv-task-import`.**
  *2026-10-25:* подтверждено практикой первого реального проекта (ключ Jira = имя
  файла); вошло в этап 6
  плана универсальной установки (os-v7). Открытые вопросы ниже остаются за владельцем.
  Если задача пришла извне (Jira, Obsidian, YouTrack, GitHub Issues, Linear…), ОС её
  не видит: бэклог — это только файлы `Project-OS/03-Development/Tasks/`, шаблон
  Task не умеет хранить внешний ключ, а Context Provider принципиально не пишет
  (`managed_write` нет). Ассистент, получив тикет в чат, по `CLAUDE.md` ищет текущую
  Task, не находит её, и дальше правил нет. Пробел в процессе, не в коде.

  **Требование владельца:** не привязываться к Jira. Задача подтягивается из любого
  ресурса, доступного через MCP, по явной команде пользователя:
  `/mv-task-import <resource> [<epic>] [<task>]`. Указан только эпик — тянутся все
  его задачи.

  **Предлагаемое устройство — два слоя, граница между ними — нейтральный JSON.**
  1. *Получение (команда, недетерминированно).* `.claude/commands/mv-task-import.md`
     ищет инструменты `mcp__<resource>__*`, достаёт элемент и нормализует его в
     нейтральную форму: `{resource, id, url, kind: epic|task, title, description,
     acceptance, external_status, updated, parent, children[]}`. Ни одного
     ресурса в коде нет: команда работает с тем, что объявляет MCP-сервер. Для
     ресурсов, где «эпик» и «дети» выражены неочевидно, — необязательные подсказки
     в одном файле (`Knowledge-OS/Tools/import-hints.json`: Jira — тип Epic, дети
     через `parent = KEY`; Obsidian — `type: epic` и `contains::`). Нет подсказки —
     команда выводит связь из схемы инструментов и называет, как она это сделала.
  2. *Запись (скрипт, детерминированно и с тестами).* `task-import.mjs` принимает
     нормализованный JSON на stdin и пишет файлы по шаблонам: следующий номер `Txx`,
     Epic с `contains::` (создаёт или находит существующий по `origin`),
     `status: todo`, `lifecycle: draft`, новое поле
     `origin: {resource, id, url, imported, updated}`. По умолчанию — `--dry-run`:
     показывает, что будет создано, и пишет только после подтверждения.

  **Правила, которые делают это безопасным:**
  - *Снимок, а не синхронизация.* После импорта источник истины — Task в хранилище;
    статус обратно не пишется, внешний трекер не становится писателем знания проекта.
    Это совместимо с [[Knowledge-OS/Protocols/Context-Provider-Protocol]]: импорт
    запускает человек, результат лежит в `draft`. Автоматическое создание по событию
    трекера — уже другое, и требует Decision.
  - *Идемпотентность по `origin.id`.* Повторный импорт той же задачи не плодит дубль:
    если Task ещё `todo` — обновляет тело, если работа начата — показывает расхождение
    и ничего не перезаписывает.
  - *Закрытые во внешнем ресурсе по умолчанию пропускаются* (`--include-closed` —
    явный флаг).
  - *Текст тикета — данные, не инструкции.* Описание из трекера пишет кто угодно; его
    содержимое не исполняется как указание ассистенту.
  - *Ресурс недоступен — отказ с причиной*, без тихой подмены. Запасной путь —
    `resource = paste`: пользователь вставляет текст, дальше тот же скрипт.

  **Открытые вопросы для решения перед реализацией:**
  - Разбор аргументов: `<resource> <X>` неоднозначно (эпик или задача?). Варианты —
    один `<ref>` и тип берётся из ресурса, или явное `--epic <name> [<task>]`.
    Склоняюсь к первому с подтверждением в `--dry-run`.
  - Нумерация: импортированные Task получают следующие номера и тем самым встают в
    конец очереди «наименьший открытый номер — следующий». Нужно ли вставлять их в
    начало — вопрос владельца.
  - `evidence` импортированной Task: подходит ли `user-provided` (утверждение
    владельца задачи, не наблюдение), или `evidence` до начала работы не ставить.
  - Поле `origin` — в `schema.json` и `Metadata-Schema`, чтобы валидатор знал его.

### `foreignNotes` помечает служебные файлы агента

Внесено 2026-09-11 по итогам сверки Э3 (T13).

Правило `foreignNotes` в `context-metrics.mjs` (добавлено патчем Э1, M9 аудита)
помечает любой `.md`, адресованный абсолютным путём вне VAULT. Оно ловит то, для
чего сделано: чтение хранилища из другого рабочего дерева, молча уезжающее в
bucket `evidence`.

Но в сессии T13 оно сработало на `~/.claude/plans/<id>.md` — файле
плана самой сессии. Срабатывание формально верное (это markdown вне хранилища,
и он действительно посчитан как `evidence`), но к подмене путей отношения не
имеет: ни одна заметка хранилища не была ошибочно классифицирована.

Пока это один путь на сессию — шум терпимый. Если служебных markdown-файлов
агента станет больше, предупреждение начнёт выглядеть фоном и его перестанут
читать, ровно как это произошло с `stale` и `⚠️` в QA.

Вариант правки: исключить из `foreignNotes` пути под `~/.claude/`, оставив
проверку для всего остального. Не делать до тех пор, пока срабатываний не
станет больше одного-двух за сессию — иначе это правка ради гипотезы.

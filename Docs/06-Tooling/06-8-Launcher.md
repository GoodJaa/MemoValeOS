# 6.8. Лаунчер mv.cjs: инструменты на Node хоста

> **Описывает:** [[Knowledge-OS/Tools/mv.cjs]], [[Knowledge-OS/Tools/mv.test.mjs]], переменную окружения `MVOS_NODE`
> **Связано:** [[Docs/07-Commands]] — команды, которые вызывают инструменты только через лаунчер, [[Docs/06-Tooling/06-7-OS-Check]] — CI, где лаунчер запускается старым Node, [[Docs/08-Distribution/08-2-Adoption]] — установка, первая точка, где Node хоста имеет значение

## Назначение

Инструментам слоя ОС нужен Node 18 или новее. Node хоста по умолчанию бывает старше: на первом реальном проекте это был Node 12 (`.nvmrc` проекта). Там каждый инструмент падал на `??` с `SyntaxError`, а ассистент за 24 сессии 209 раз набирал путь к новому Node вручную, 27 раз спрашивал `node -v` и 11 раз смотрел `ls ~/.nvm`. Вопрос «какой Node?» задавался в каждой сессии заново.

`mv.cjs` отвечает на него один раз: он запускается любым `node`, сам находит подходящий и им запускает инструмент.

```bash
node "Knowledge-OS/Tools/mv.cjs" validate-vault            # любой инструмент из Tools/, без .mjs
node "Knowledge-OS/Tools/mv.cjs" adopt --verify            # аргументы передаются как есть
node "Knowledge-OS/Tools/mv.cjs" doctor                    # каким Node будут запускаться инструменты и почему
node "Knowledge-OS/Tools/mv.cjs" doctor --json
MVOS_NODE=/opt/nvm/versions/node/v18.20.8/bin/node node "Knowledge-OS/Tools/mv.cjs" doctor
```

Коды выхода: код самого инструмента; `2` — неизвестный инструмент; `3` — нет Node 18 или новее.

## Как работает

### Выбор Node

1. **`MVOS_NODE`**, если задана. Если она указывает на слишком старый Node или на несуществующий файл, лаунчер отказывает, а не подменяет явную настройку молча.
2. **Node, которым запущен сам лаунчер**, если он не старше 18. Это обычный случай.
3. **Самый новый Node ≥ 18 из найденных.** Поиск идёт по всем каталогам `PATH` (не только по первому совпадению), по nvm (`$NVM_DIR`, `~/.nvm`, `/opt/nvm`, `/usr/local/nvm`, каталоги `versions/node/v*`) и по nvm-windows (`%NVM_HOME%\v*`, `%NVM_SYMLINK%`). Версию дают имена каталогов nvm. Для остальных бинарников — один вызов `--version`.
4. **Отказ** с кодом 3. Сообщение перечисляет все найденные бинарники с версиями и говорит, как исправить: поставить Node 18+ или указать `MVOS_NODE`.

Выбранный Node запускает `Tools/<инструмент>.mjs` дочерним процессом. `stdin`, `stdout` и `stderr` передаются насквозь (это нужно `context-provider`, который читает запрос из stdin), а код выхода становится кодом лаунчера.

Список инструментов — все `*.mjs` в `Knowledge-OS/Tools/`, кроме `*.test.mjs`. Отдельного реестра нет: новый инструмент доступен через лаунчер сразу.

### ECMAScript 5

`mv.cjs` — единственный файл слоя, написанный на CommonJS и ES5: `var`, функции без стрелок, без шаблонных строк. Старый Node должен **разобрать** этот файл, прежде чем тот найдёт новый. Один `?.` сломал бы лаунчер ровно там, где он нужен, а Node, на котором гоняют тесты, никогда не бывает таким старым. Поэтому синтаксис закреплён тестом: `mv.test.mjs` разбирает файл через `acorn` как ECMAScript 5 (`ecmaVersion: 5`, `sourceType: "script"`).

Функции выбора экспортированы через `module.exports`: `parseVersion`, `compareVersions`, `findCandidates(env, home, probe)`, `chooseNode(current, explicit, candidates)`. Тест описывает машину, а не ищет её: фиктивное дерево nvm во временном каталоге, явный `MVOS_NODE`, «ничего подходящего».

## Почему так

**Один вход, а не проверка версии в каждом инструменте.** Проверка внутри `.mjs` не помогает: файл с `??` не разбирается старым Node, и до проверки дело не доходит. Лаунчер — отдельный файл, который старый Node прочитать может.

**Дочерний процесс, а не `import()`.** Динамический `import()` в CommonJS — синтаксис ES2020, его ES5-разбор не пропустит. Цена дочернего процесса — десятки миллисекунд на вызов, и это дешевле, чем набирать путь к Node вручную.

**Самый новый, а не первый найденный.** Каталоги `PATH` идут в порядке, который хост выбрал для себя: на первом реальном проекте первым стоял Node 12, потому что этого требует фронтенд проекта. Инструментам ОС нужен не Node проекта, а Node не старше 18.

**`MVOS_NODE` не переопределяется.** Если человек указал конкретный бинарник, молча выбрать другой значило бы спрятать ошибку настройки.

## Пример

Хост первого реального проекта: в `PATH` Node 12 (`.nvmrc` проекта), в `/opt/nvm` — 18.20.8 и 20.20.2.

```text
$ node MemoValeOS/Knowledge-OS/Tools/mv.cjs doctor
MemoValeOS doctor
  vault         /home/…/project/MemoValeOS  (os-v6)
  needs Node    18 or newer
  launcher Node v12.22.12  /usr/bin/node
  MVOS_NODE     not set
  tools run on  v20.20.2  /opt/nvm/versions/node/v20.20.2/bin/node  — the newest Node >= 18 found (nvm (/opt/nvm))
  found:
    v12.22.12  /usr/bin/node  (PATH)
    v18.20.8  /opt/nvm/versions/node/v18.20.8/bin/node  (nvm (/opt/nvm))
    v20.20.2  /opt/nvm/versions/node/v20.20.2/bin/node  (nvm (/opt/nvm))
```

`/mv-check` на том же хосте вызывает `node ".../mv.cjs" validate-vault`. Голый `node` — двенадцатый, но валидатор запускается двадцатым.

## Подводные камни

- **`node` должен быть хоть какой-то.** Если в `PATH` нет никакого `node`, лаунчер не запустится — его самого нечем выполнить. Тогда вызывайте нужный Node по полному пути: `/opt/nvm/versions/node/v18.20.8/bin/node MemoValeOS/Knowledge-OS/Tools/mv.cjs doctor`.
- **fnm, volta, asdf, nodenv** не ищутся. Их Node виден, только если его каталог в `PATH`. Иначе используйте `MVOS_NODE`.
- **Хук `budget-audit` идёт не через лаунчер.** Он срабатывает на каждый Read/Grep/Glob, и лишний процесс там слишком дорог. Хук сам написан так, чтобы его разобрал и выполнил старый Node: CommonJS и ECMAScript 2017, начиная с Node 8. На хосте с Node 12 он пишет журнал, а при любом сбое выходит с кодом 0 ([[Docs/06-Tooling/06-4-Budget-Audit-Hook]]).
- **Obsidian и Claude Desktop** запускают Node не из оболочки и не видят переменных nvm. Лаунчер ищет nvm и по фиксированным путям, но для них надёжнее системный Node (README, «Про Node»).

## Как менять

- **Новый менеджер версий** — ещё один блок `add(...)` в `findCandidates`, плюс случай в тесте «candidates are found in nvm and nvm-windows trees».
- **Минимальный Node** — константа `MIN_MAJOR`, `engines` в [[package.json]], README и нижний Node в матрице CI (`.github/workflows/os-check.yml`).
- **Любая правка `mv.cjs`** — только синтаксисом ES5. Тест на `acorn` упадёт на первом `let` или `=>`.
